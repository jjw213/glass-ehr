# 사번 체계 설계안 (#9)

결정: **사업장 코드 + 입사연도 + 순번**. 예: `S01-2026-001`
(2026-11-11 사람 답변. 사업장이 여러 곳일 때를 대비)

## 1. 형식
`{사업장코드}-{입사연도}-{순번}` — 구분자는 하이픈(`-`), 전체 12자.

| 부분 | 형식 | 예 | 설명 |
|---|---|---|---|
| 사업장코드 | `S` + 숫자 2자리 | `S01` | 사업장(근무지) 마스터의 코드. 예시 형식을 그대로 따름 |
| 입사연도 | 숫자 4자리 | `2026` | 입사일(`Asia/Seoul` 기준)의 연도 |
| 순번 | 숫자 3자리, 0 채움 | `001` | 같은 사업장·같은 입사연도 안에서 001부터 차례로 부여 |

- 검증 정규식(초안): `^S\d{2}-\d{4}-\d{3}$`
- 연도가 바뀌면 순번은 001부터 다시 시작한다(연도가 사번에 들어 있으므로 겹치지 않음).
- 사번에는 생년월일·주민등록번호 등 개인정보를 넣지 않는다. 따라서 사번은 고유식별정보가 아니며 화면·로그에 마스킹 없이 표시할 수 있다.

## 2. 저장·채번 (구현 이슈에서)
- 사원 테이블의 `emp_no VARCHAR2(12)`에 UNIQUE 제약. 내부 키는 별도의 불변 `emp_id`를 쓰고, 다른 테이블은 `emp_id`로 참조한다(사번 형식이 나중에 바뀌어도 참조가 깨지지 않게).
- 순번은 사업장·연도마다 다시 시작하므로 Oracle 시퀀스 하나로는 만들 수 없다. 채번 테이블 `emp_no_seq(site_code, hire_year, last_seq)`를 두고, 사원 등록 트랜잭션 안에서 `SELECT ... FOR UPDATE`로 잠근 뒤 `last_seq + 1`을 쓴다. 롤백되면 순번도 되돌아가 빈 번호가 생기지 않는다.
- 동시에 두 명을 등록해도 같은 번호가 나오지 않는지 테스트한다.

## 3. 아직 정하지 않은 것 (사원 등록 구현 이슈에서 질문)
- 사업장 간 전보 시 사번을 유지할지, 새 사업장 코드로 다시 부여할지
- 퇴직 후 재입사 시 기존 사번을 다시 쓸지, 새로 부여할지 (퇴직자 사번을 다른 사람에게 재사용하지 않는 것은 UNIQUE 제약으로 보장)
- 같은 사업장·같은 해 입사자가 999명을 넘을 때의 처리
- 입사일을 정정해 연도가 바뀌는 경우 사번을 다시 부여할지
