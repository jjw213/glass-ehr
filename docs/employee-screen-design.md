# 사원 목록·인사기록카드 화면 (#15)

선행: 사원 기본정보 API(#14, `docs/employee-design.md`), 조직 트리(#12), 공통코드(#11), 주민등록번호 처리(#10, `docs/rrn-design.md`).
코드: `frontend/src/pages/PeoplePage.tsx`(화면), `frontend/src/api/employees.ts`(API·검색·검사·데모용 가짜 백엔드),
`frontend/src/lib/privacy.ts`(표시 권한), `frontend/src/data/employees.ts`(가짜 시드).

## 1. 데이터 출처
- 목록 `GET /api/employees?includeRetired=true`, 상세 `GET /api/employees/{id}`, 등록 `POST /api/employees`,
  주민등록번호 원문 `GET /api/employees/{id}/rrn?purpose=VIEW`, 부서 `GET /api/org/tree?date=오늘`. 모두 Spring 백엔드(`vite.config.ts` 프록시).
- 등록·원문 조회 요청에는 임시 헤더 `X-Actor-Id`(로그인 ID)·`X-Actor-Role`을 붙인다(#14와 같은 임시 방식, 인증 이슈에서 교체).
- `VITE_API=mock`이면 `createMockEmployeeApi()`(가짜 사원 14명, 주민등록번호 없음)를 쓴다.
- 기존 Node 서버 bootstrap의 `employees`(이메일·연락처 등 데모 값)는 이 화면에서 더 쓰지 않는다. 홈·조직도 화면은 그대로.

## 2. 목록·검색
- 이름·사번 부분 검색(사번은 대소문자 무시), 부서(선택한 부서의 하위부서 포함)·직급·재직상태 필터. 30인 이상 규모라 목록을 한 번에 받아 화면에서 거른다.
- 재직상태는 날짜만으로 정한다(Asia/Seoul 오늘 기준): 입사일 전 `입사예정`, 퇴직일이 있고 당일까지 `퇴직예정`(재직 필터에 포함), 퇴직일 다음 날부터 `퇴직`.
  퇴직일 당일까지 재직으로 보는 규칙은 백엔드 `EmployeeDeptMemberChecker`와 같다. **휴직**은 발령 이력이 생기면 추가한다.
- 모바일(899px 이하): 표 머리글과 부가 열(직책·고용형태·입사일)을 숨기고 한 사람당 카드 한 줄(성명·상태 / 사번·부서·직급)로 보인다.
  인사기록카드는 아래에서 올라오는 시트, 등록 폼은 한 열로 바뀐다.

## 3. 개인정보 표시 규칙 (`lib/privacy.ts`)
| 항목 | 인사담당(HR) | 급여담당(PAYROLL) | 관리자(ADMIN) | 일반 직원 |
|---|---|---|---|---|
| 생년월일 | 보임 | 보임 | 보임 | `****-**-**` |
| 주소 | 보임 | 보임 | 보임 | 첫 단위만(`가상시 ***`) |
| 이력·종사 업무·기타 | 보임 | 보임 | 보임 | 비공개 |
| 주민등록번호 | 마스킹 값 + 원문 보기 | 마스킹 값 + 원문 보기 | 마스킹 값만 | 비공개 |
| 근로계약·근태 요약 탭 | 보임 | 보임 | 보임 | 잠금 |
| 신규 등록 | 가능 | 불가 | 가능 | 불가 |

- 주민등록번호 원문 보기 권한은 `docs/rrn-design.md` 3장·백엔드 `RequestActor.canRevealRrn`과 같다(관리자 불가). 원문은 누를 때만 받아 30초 뒤 다시 가리고, 서버가 매번 조회 로그를 남긴다.
- 등록 폼의 주민등록번호 입력은 `password` 칸이고, 저장 뒤 화면 상태에서 지운다. 오류 메시지에 입력값을 넣지 않는다.
- 일반 직원 열은 가장 보수적으로 정한 **잠정 규칙**이다. 본인 카드 예외(내 정보는 다 보기)는 로그인 사용자와 `emp_id`를 잇는 인증 이슈에서 붙인다.
- **이 규칙은 화면 표시용이다.** 지금 백엔드 상세 API는 권한 없이 주소·생년월일을 돌려준다. 서버 쪽 필드 마스킹·권한 검사는 백엔드 인증·권한 이슈에서 붙여야 한다.

## 4. 인사기록카드 탭
- 인적사항: 시행령 제20조 기재사항 중 인적 항목(#14 매핑 그대로).
- 발령 이력: 발령 테이블이 아직 없어 입사(입사 시 소속·직급·직책)와 퇴직만 보인다. 부서명은 오늘 기준 조직명. 인사발령 이슈에서 발령 이력 API로 바꾼다.
- 근로계약: 고용형태·입사일·갱신일·계약기간·1주 소정근로시간(분 → 시간·분 표시)·근무지·메모·퇴직 정보·명부 보존기한.
- 근태 요약: 근태 모듈(2단계) 전이라 안내 문구만 둔다(모듈 순서 규칙). 근태 집계 이슈에서 채운다.

## 5. 남은 일 / 확인 필요
- 사업장 목록 API가 없어 등록 폼의 사업장코드는 직접 입력(기본 `S01`)이다.
- 법령 계산은 없다. `privacy.ts` 주석의 개인정보 보호법 제3조(최소 처리 원칙) 인용은 law.go.kr 원문을 자동으로 확인하지 못해 사람이 다시 확인해야 한다.
