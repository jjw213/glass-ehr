# legal_rate 설계안 (#3)

상태: 설계 초안. 법정 수치·코드 목록은 입력되지 않았으며, 이 문서는 실행용 시드 데이터를 포함하지 않는다.

## 1. 결정 및 범위

- DB는 Oracle, 스키마 생성은 SQL 마이그레이션으로 관리한다. JPA는 `ddl-auto: validate`로만 사용한다.
- 기준값은 MyBatis SQL로 직접 조회한다.
- 항목은 `item_code`로 식별한다. 기간은 날짜 단위이며 시작일 포함, 종료일 제외 `[effective_from, effective_to)`로 정의한다. 종료일 `NULL`은 종료일이 정해지지 않은 현재 유효 기간이다.
- 조회일에 해당하는 행은 정확히 하나여야 한다. 값이 없거나 두 건 이상이면 호출자가 조용히 기본값을 적용하지 않고 데이터 오류로 처리한다.
- 현재 이슈의 설계 범위는 구조와 조회 계약이다. 법정 수치, 항목코드 목록, 실제 근거 조문·URL은 검증 후 사람이 입력한다.

## 2. Oracle DDL

`legal_rate_item`은 항목 코드별 쓰기 잠금 행이자 코드 사전이다. 항목코드 추가는 검토된 코드로 이 테이블에 먼저 등록한다. 항목 목록과 수치는 이 설계안에서 확정하지 않는다.

```sql
CREATE TABLE legal_rate_item (
    item_code       VARCHAR2(64 CHAR)  NOT NULL,
    item_name       VARCHAR2(200 CHAR) NOT NULL,
    CONSTRAINT pk_legal_rate_item PRIMARY KEY (item_code)
);

CREATE TABLE legal_rate (
    legal_rate_id   NUMBER(19) GENERATED BY DEFAULT AS IDENTITY NOT NULL,
    item_code       VARCHAR2(64 CHAR)  NOT NULL,
    effective_from  DATE               NOT NULL,
    effective_to    DATE,
    rate_value      NUMBER(18, 6)      NOT NULL,
    unit            VARCHAR2(32 CHAR)  NOT NULL,
    legal_basis     VARCHAR2(1000 CHAR) NOT NULL,
    source_url      VARCHAR2(2000 CHAR) NOT NULL,
    created_at      TIMESTAMP(6) DEFAULT SYSTIMESTAMP NOT NULL,
    created_by      VARCHAR2(100 CHAR) NOT NULL,

    CONSTRAINT pk_legal_rate PRIMARY KEY (legal_rate_id),
    CONSTRAINT fk_legal_rate_item
        FOREIGN KEY (item_code) REFERENCES legal_rate_item (item_code),
    CONSTRAINT ck_legal_rate_date_only
        CHECK (effective_from = TRUNC(effective_from)
           AND (effective_to IS NULL OR effective_to = TRUNC(effective_to))),
    CONSTRAINT ck_legal_rate_period
        CHECK (effective_to IS NULL OR effective_from < effective_to),
    CONSTRAINT ck_legal_rate_unit
        CHECK (LENGTH(TRIM(unit)) > 0),
    CONSTRAINT ck_legal_rate_basis
        CHECK (LENGTH(TRIM(legal_basis)) > 0),
    CONSTRAINT ck_legal_rate_url
        CHECK (LENGTH(TRIM(source_url)) > 0),
    CONSTRAINT uq_legal_rate_item_from UNIQUE (item_code, effective_from)
);

CREATE INDEX ix_legal_rate_item_period
    ON legal_rate (item_code, effective_from, effective_to);
```

`rate_value`는 요율·금액·시간급 등 다양한 기준값을 표현하기 위한 십진수다. 실제 단위(예: 원/시간, 비율의 저장 스케일)는 항목 정의에서 명시하며, 수치 검증 과정에서 필요한 정밀도와 허용 범위를 확정한다. 금액 계산에 부동소수점 타입을 쓰지 않는다.

## 3. 중복·겹침 방지

- `uq_legal_rate_item_from`: 같은 항목의 같은 시작일 중복을 DB가 거부한다.
- 날짜·기간 CHECK: 시간 성분이 있는 날짜, 종료일이 시작일보다 빠르거나 같은 기간을 거부한다.
- Oracle은 범위 겹침을 직접 표현하는 exclusion constraint를 제공하지 않는다. 애플리케이션에서 검사만 하면 동시 쓰기 경쟁으로 겹침이 들어갈 수 있으므로, 쓰기는 아래 직렬화 절차를 거치는 단일 저장 프로시저(또는 이에 준하는 트랜잭션 서비스)로 제한한다.
  1. 트랜잭션에서 해당 `legal_rate_item` 행을 `SELECT ... FOR UPDATE`로 잠근다.
  2. 같은 `item_code`에 대해 기존 기간과 입력 기간의 겹침 여부를 검사한다.
  3. 겹침이 없을 때만 INSERT/UPDATE한다. 충돌 시 롤백하고 명확한 도메인 오류를 반환한다.
  4. 애플리케이션 DB 계정은 `legal_rate` 직접 DML 권한을 갖지 않고 저장 프로시저 실행 권한만 갖도록 한다. 배포/운영 계정만 마이그레이션 권한을 가진다.

후보 기간 `[p_from, p_to)`와 기존 기간 `[effective_from, effective_to)`의 겹침 조건:

```sql
existing.effective_from < NVL(:p_to, DATE '9999-12-31')
AND (existing.effective_to IS NULL OR :p_from < existing.effective_to)
```

이 조건은 경계가 맞닿는 연속 기간(기존 종료일 = 다음 시작일)은 허용하고, 하루라도 공통 날짜가 있는 기간은 거부한다. 잠금은 같은 항목 코드의 쓰기만 직렬화하며, 여러 항목을 한 트랜잭션에서 수정할 경우 코드 오름차순으로 잠가 데드락 가능성을 줄인다. 실제 프로시저 본문과 권한 스크립트는 쓰기 운영 방식 확정 후 구현한다.

## 4. 날짜 기준 조회 SQL

조회 기준일은 Java `LocalDate`로 전달한다. MyBatis에서 Oracle 바인드 값은 `#{asOfDate, jdbcType=DATE}`로 처리하고, SQL 비교는 반개구간으로 한다.

```sql
SELECT
    item_code,
    effective_from,
    effective_to,
    rate_value,
    unit,
    legal_basis,
    source_url
FROM legal_rate
WHERE item_code = #{itemCode}
  AND effective_from <= #{asOfDate, jdbcType=DATE}
  AND (effective_to IS NULL OR #{asOfDate, jdbcType=DATE} < effective_to)
```

Mapper 반환은 단건 조회 계약으로 둔다. 결과 0건은 미등록 기준값, 2건 이상은 겹침 데이터 오류다. 운영 조회에서 `FETCH FIRST 1 ROW`로 중복을 감추지 않는다. 시작일 포함·종료일 제외이므로 종료일과 같은 날에는 구간이 유효하지 않고, 종료일과 같은 날짜의 다음 구간 시작은 유효하다.

## 5. MyBatis 조회 인터페이스

패키지명은 기존 `com.glassehr` 기준의 제안이며, 실제 모듈 구성 시 맞춘다.

```java
package com.glassehr.legalrate;

import java.time.LocalDate;
import java.util.List;
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Param;

@Mapper
public interface LegalRateMapper {
    List<LegalRateRow> findEffective(
        @Param("itemCode") String itemCode,
        @Param("asOfDate") LocalDate asOfDate
    );
}
```

서비스 계층은 결과가 1건인지 검증한 뒤 `Optional<LegalRate>` 또는 명시적 미등록 예외로 변환한다. 0건/다건을 구분해 오류를 기록하되 법정 기준값 자체나 사용자 개인정보는 로그에 남기지 않는다. MyBatis XML은 `backend/src/main/resources/mapper/legalrate/LegalRateMapper.xml`, 결과 DTO는 `backend/src/main/java/com/glassehr/legalrate/LegalRateRow.java` 위치를 제안한다. DTO의 값 타입은 `BigDecimal`, 기간은 `LocalDate`를 사용한다.

## 7. 테스트 케이스

법령 정답값이 아닌 고정된 테스트용 날짜/값으로 조회 계약과 데이터 무결성만 검증한다. 실제 법정 수치 fixture는 사람이 원문 대조를 마친 뒤 별도 입력한다. Oracle 날짜 타입, 제약, 잠금 동작을 검증하는 통합 테스트를 Oracle 테스트 DB에서 실행한다. H2만으로 Oracle 고유 동작을 대신 검증하지 않는다.

| 종류 | Given | 기대 |
|---|---|---|
| 시작 경계 | 조회일 = `effective_from` | 해당 행 1건 |
| 기간 중간 | 시작일 < 조회일 < 종료일 | 해당 행 1건 |
| 종료 경계 | 조회일 = `effective_to` | 해당 행 0건 |
| 연속 구간 경계 | A 종료일 = B 시작일, 조회일 = 경계일 | B만 1건 |
| 열린 종료 | 종료일 NULL, 조회일 ≥ 시작일 | 해당 행 1건 |
| 미래 구간 | 조회일 < 시작일 | 0건 |
| 미등록 코드 | 해당 코드 행 없음 | 0건, 서비스는 미등록 오류 |
| 동일 시작일 중복 | 같은 코드·시작일 INSERT | UNIQUE 위반 |
| 역전/빈 구간 | 종료일 ≤ 시작일 | CHECK 위반 |
| 날짜 시각 성분 | 시작일 또는 종료일에 00:00 외 시간 존재 | CHECK 위반 |
| 겹침 | `[2026-01-01, 2026-04-01)`에 겹치는 기간 입력 | 쓰기 절차가 거부 |
| 맞닿는 기간 | `[2026-01-01, 2026-04-01)` 다음 `[2026-04-01, NULL)` | 쓰기 성공 |
| 동시 겹침 입력 | 같은 코드의 중첩 후보를 두 트랜잭션에서 동시 제출 | 한 건만 성공 |
| 조회 중복 방어 | 겹침 데이터를 테스트에서 강제로 조성 | Mapper 다건, 서비스 데이터 오류 |

테스트의 날짜 예시는 경계 동작 설명용이며 실제 법령 시행일을 의미하지 않는다. 동시성 테스트의 강제 데이터 조성은 테스트 전용 DB/권한으로 격리한다.
