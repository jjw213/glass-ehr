# 출퇴근 기록 방식 설계안 (#22)

결정: **출근·퇴근 버튼으로 기록하고, 누를 때 GPS 위치로 사업장 반경 안인지 확인한다.
위치정보 수집 동의와 보관 정책을 함께 둔다**
(2026-11-11 사람 답변, 텔레그램)

관련 법령(원문 미확인 — 구현 이슈에서 law.go.kr로 확인 후 확정, §7):
- 개인정보 보호법 — 위치정보 수집·이용 동의(제15조·제22조), 최소 수집, 보유기간 경과 시 파기(제21조)
- 위치정보의 보호 및 이용 등에 관한 법률 — 회사가 직접 운영하는 출퇴근 앱에 적용되는지(사업자 신고 대상 여부) 확인 필요
- 근로자참여 및 협력증진에 관한 법률 — 근로자 감시 설비 관련 노사협의회 협의 대상에 해당하는지 확인 필요

이 문서는 구조만 정한다. 조문 번호·보관 기간 같은 수치는 기억으로 확정하지 않는다.

## 1. 기록 흐름
1. 직원이 화면(웹·모바일 브라우저)에서 **출근** 또는 **퇴근** 버튼을 누른다.
2. 브라우저 Geolocation API로 위도·경도·정확도(m)를 받는다. 위치 동의가 없으면 위치를 요청하지 않는다(§4).
3. 서버가 **서버 시각**(`Asia/Seoul`)으로 기록 시각을 정한다. 단말 시각은 참고용으로만 저장하고 근태 계산에 쓰지 않는다(단말 시계 조작 방지).
4. 서버가 사원의 근무 사업장 좌표와 거리를 계산해 반경 안/밖을 판정한다(§3).
5. 판정 결과와 함께 기록 한 행을 **추가**한다. 기록은 수정·삭제하지 않는다.

- 근태 시간(분 단위 정수)은 이 원시 기록에서 집계 단계가 계산한다. 이 이슈는 기록 방식만 다룬다.
- 같은 종류 버튼을 짧은 시간 안에 여러 번 누르면 모두 저장하고, 집계 규칙(첫 출근·마지막 퇴근 등)은 근무일정·집계 이슈에서 정한다.

## 2. 테이블 초안
### `attendance_punch` (출퇴근 원시 기록, 추가만)
| 컬럼 | 설명 |
|---|---|
| `punch_id` | PK |
| `emp_id` | 사원 (불변 내부 키, #9) |
| `punch_type` | `IN` / `OUT` |
| `punched_at` | 서버 기록 시각 (`TIMESTAMP WITH TIME ZONE`, Asia/Seoul) |
| `client_time` | 단말이 보낸 시각(참고용) |
| `work_date` | 귀속 근무일(야간 근무의 날짜 넘김 처리는 근무일정 이슈에서) |
| `site_id` | 판정에 쓴 사업장 |
| `geo_status` | `INSIDE` / `OUTSIDE` / `NO_CONSENT` / `UNAVAILABLE`(권한 거부·측정 실패) |
| `distance_m` | 사업장 기준점까지 거리(정수 m). 위치 없으면 NULL |
| `accuracy_m` | 단말이 보고한 정확도(정수 m) |
| `source` | `WEB` / `MOBILE_WEB` / `ADMIN`(관리자 대리 입력) |
| `created_at` | |

### `attendance_punch_location` (좌표 원문, 짧게 보관 후 파기)
| 컬럼 | 설명 |
|---|---|
| `punch_id` | PK, FK → `attendance_punch` |
| `latitude`, `longitude` | 좌표 원문 |
| `purge_after` | 파기 예정일 (보관 기간 정책으로 계산, §5) |

- 좌표 원문은 별도 테이블에 둔다. 판정 결과(`geo_status`, `distance_m`)는 근태 기록과 함께 오래 남기고, 좌표 원문은 보관 기간이 지나면 행을 지운다.
  근태 분쟁 대응에 필요한 것은 "반경 안이었는지"이고, 좌표 자체를 오래 둘 필요는 적다는 판단(최소 수집).
- 좌표는 애플리케이션 로그에 남기지 않는다.

### `work_site_geofence` (사업장 위치, 유효기간 방식)
| 컬럼 | 설명 |
|---|---|
| `site_id` | 사업장 (#9 사업장코드) |
| `latitude`, `longitude` | 기준점 |
| `radius_m` | 허용 반경(정수 m) — 회사가 정하는 운영 설정값(법정 기준값 아님) |
| `valid_from`, `valid_to` | 유효기간 (#8과 같은 `[valid_from, valid_to)`) |

- 사업장 이전·반경 변경 이력을 남겨 과거 기록의 판정을 다시 확인할 수 있게 한다.
- 테이블·마이그레이션은 사원·사업장 테이블이 생기는 근태 구현 이슈에서 만든다(이번 이슈는 결정 기록만, 마이그레이션 번호 사용 안 함).

## 3. 반경 판정
- 거리는 기준점과 측정 좌표의 대권 거리(하버사인)로 계산하고 정수 m로 버린다.
- 판정: `distance_m <= radius_m` 이면 `INSIDE`. 단말 정확도(`accuracy_m`)가 매우 나쁜 경우의 처리(재측정 요청 / 그대로 기록)는 §7 미결.
- **반경 밖이어도 기록은 막지 않는다.** `OUTSIDE`로 저장하고 관리자 확인 대상으로 표시한다.
  외근·출장·재택이 있으므로 기록 자체를 거부하면 실제 근로시간이 누락될 수 있다. 막을지 여부는 §7 미결.

## 4. 위치정보 수집 동의
### `location_consent` (동의 이력, 추가만)
| 컬럼 | 설명 |
|---|---|
| `consent_id` | PK |
| `emp_id` | 사원 |
| `consent_version` | 동의서 문안 버전 |
| `action` | `AGREE` / `WITHDRAW` |
| `acted_at` | 일시 (Asia/Seoul) |
| `ip` | 접속 IP |

- 처음 출퇴근 버튼을 누르기 전에 동의 화면을 보여 준다. 문안에는 수집 항목(좌표·정확도), 목적(출퇴근 위치 확인), 보유 기간, 거부 권리와 거부 시 처리 방법을 적는다. 문안 확정은 §7.
- 동의 철회는 언제든 할 수 있고, 철회 후 버튼을 누르면 위치를 요청하지 않고 `NO_CONSENT`로 기록한다.
- **동의하지 않아도 출퇴근 기록은 할 수 있게 한다**(`NO_CONSENT`로 저장, 관리자 확인). 동의 거부를 이유로 불이익을 주지 않는다는 원칙에 맞추기 위함 — 해당 조문은 구현 이슈에서 원문 확인.
- 문안이 바뀌면 `consent_version`을 올리고 다시 동의를 받는다.

## 5. 보관 정책
| 대상 | 보관 | 파기 |
|---|---|---|
| `attendance_punch` (시각·판정 결과) | 근태·임금 기록 보존 기간 동안 (근로기준법상 서류 보존 기간 — 원문 확인 후 확정) | 기간 경과 후 파기 절차 |
| `attendance_punch_location` (좌표 원문) | 짧은 기간(기간은 §7 미결) | `purge_after`가 지난 행을 매일 배치로 삭제, 삭제 건수만 로그 |
| `location_consent` | 동의 사실 입증을 위해 퇴직 후 일정 기간 | 기간은 §7 미결 |

- 보관 기간 숫자는 코드에 쓰지 않고 회사 설정(유효기간 방식)에서 읽는다. 법정 보존 기간이 있는 항목은 `legal_rate` 항목으로 추가한다(구현 이슈).

## 6. 관리자 확인·정정
- `OUTSIDE` / `NO_CONSENT` / `UNAVAILABLE` 기록과 기록 누락일은 관리자 확인 목록에 나온다.
- 정정은 원시 기록을 고치지 않고, 정정 요청·승인 행을 따로 추가한다(요청자, 사유, 정정 시각, 승인자). 집계는 승인된 정정을 반영한다.
- 관리자 대리 입력은 `source = 'ADMIN'`으로 기록하고 입력자를 남긴다.
- 직원은 본인 기록만, 관리자는 담당 범위 기록을 본다. 좌표 원문은 화면에 보이지 않고 판정 결과·거리만 보인다.

## 7. 아직 정하지 않은 것 (구현 이슈에서 질문)
- 위치정보법 적용 여부(회사 자체 출퇴근 앱이 신고 대상인지) — 원문·해석 확인
- 근로자참여법상 노사협의회 협의 대상인지 — 원문 확인
- 좌표 원문 보관 기간, 동의 이력 보관 기간
- 근태 기록 법정 보존 기간 — 근로기준법 원문 확인
- 반경 밖 기록을 막을지(현재 초안: 막지 않고 표시) / 외근·출장·재택 신청과 연동 방식
- 정확도가 나쁜 측정(예: 정확도 값이 반경보다 큼)의 처리
- 기본 허용 반경 값과 사업장 하나에 기준점을 여러 개 둘지
- 동의서 문안
- 모바일 앱(네이티브) 지원 여부 — 현재 초안은 웹·모바일 브라우저만
