# 주민등록번호 처리 설계안 (#10)

결정: **저장한다 — 컬럼 단위 암호화, 화면에는 뒷자리 마스킹, 인사·급여 담당자만 원문 조회 + 조회 로그**
(2026-11-11 사람 답변, 텔레그램)

관련 법령: 개인정보 보호법 제24조의2(주민등록번호 처리의 제한), 제29조(안전조치의무).
이 문서의 법령 관련 세부 수치(접속기록 보관 기간, 암호 알고리즘 요건 등)는 아직 원문을 확인하지 않았다.
구현 이슈에서 law.go.kr 원문을 확인한 뒤 확정한다(§6).

## 1. 저장 이유와 범위
- 4대보험 취득·상실 신고, 원천징수(지급명세서 제출)에 주민등록번호가 필요하다.
  개인정보 보호법 제24조의2는 법령이 주민등록번호 처리를 구체적으로 요구하거나 허용하는 경우 등에만 처리를 허용하므로,
  **처리 근거가 되는 개별 법령 조문을 구현 이슈에서 확인해 이 문서와 코드 주석에 적는다.** (기억으로 확정하지 않음)
- 저장 대상: 재직자·퇴직자 본인의 주민등록번호. 부양가족(연말정산 등) 주민등록번호는 급여 모듈에서 별도 이슈로 다룬다.
- 외국인등록번호도 같은 방식(같은 컬럼 구조, 같은 권한·로그)으로 처리한다.

## 2. 저장 방식 — 컬럼 단위 암호화
- 사원 테이블과 분리된 테이블 `emp_rrn`에 저장한다. 사원 기본정보 조회(JPA 엔티티)에서 실수로 함께 읽히지 않게 하기 위함.

| 컬럼 | 형식 | 설명 |
|---|---|---|
| `emp_id` | `NUMBER` PK, FK → 사원 | 불변 내부 키 (#9) |
| `rrn_enc` | `RAW`/`BLOB` | 암호문. 평문 컬럼은 두지 않는다 |
| `rrn_masked` | `VARCHAR2(14)` | 화면 표시용 마스킹 값(예: `900101-1******`). 원문 복호화 없이 목록에 표시 |
| `rrn_hash` | `RAW(32)` | 중복 등록 검사용 HMAC(키는 암호화 키와 별도). 원문 복원 불가 |
| `key_version` | `NUMBER` | 암호화 키 버전(키 교체 대비) |
| `created_at`, `updated_at`, `updated_by` | | 감사 정보 |

- 암호화는 애플리케이션(Spring) 계층에서 한다. DB에는 평문이 전달되지 않는다.
  - 알고리즘 초안: AES-256-GCM(인증 암호, 레코드마다 무작위 IV). 고시(개인정보의 안전성 확보조치 기준)의 "안전한 암호 알고리즘" 요건은 구현 이슈에서 원문 확인.
  - 키는 `.env`(로컬)·운영 비밀 저장소로만 주입하고 저장소에 커밋하지 않는다. `.env.example`에는 변수 이름만 둔다.
- `rrn_masked`의 마스킹 규칙: 앞 6자리(생년월일)와 뒷자리 첫 1자리를 보이고 나머지 6자리를 `*`로 가린다.
  (답변의 "뒷자리 마스킹". 뒷자리 첫 자리까지 보일지는 §6에서 확인)

## 3. 조회 권한
| 역할 (SPEC §0) | 목록·상세 화면 | 원문 조회 |
|---|---|---|
| 관리자 | 마스킹 값 | 불가 (원문이 필요하면 인사·급여 담당 역할을 부여) |
| 인사담당 | 마스킹 값 | 가능 — "원문 보기" 버튼으로 건별 요청 |
| 급여담당 | 마스킹 값 | 가능 — 건별 요청, 신고·원천징수 파일 생성 시 시스템 내부 복호화 |
| 일반 직원 | 본인 것만 마스킹 값 | 불가 |

- 원문은 기본 응답에 절대 포함하지 않는다. 원문 조회는 별도 API(`GET /api/employees/{empId}/rrn` 초안)로만 하고, 서버에서 역할을 검사한다(화면에서 버튼을 숨기는 것만으로 막지 않음).
- 응답에 캐시 금지 헤더를 붙이고, 화면은 원문을 일정 시간 뒤 다시 가린다.

## 4. 조회 로그
- 원문 조회·복호화가 일어날 때마다 로그 테이블 `rrn_access_log`에 한 행을 추가한다(수정·삭제 불가, 추가만).
  - 항목: 조회자 ID, 대상 `emp_id`, 일시(`Asia/Seoul`), 목적 코드(화면 조회 / 4대보험 신고 / 원천징수 등), 접속 IP, 결과(성공·권한거부)
  - 로그에는 주민등록번호 원문·마스킹 값을 남기지 않는다(`emp_id`만).
- 권한 없는 원문 조회 시도도 기록한다.
- 애플리케이션 로그(로그백 등)에도 원문이 찍히지 않도록, 원문을 담는 타입의 `toString()`은 마스킹 값을 반환하게 한다.

## 5. 테스트 항목 (구현 이슈에서)
- 저장 후 DB 컬럼에 평문이 없는지(암호문·마스킹·해시만 있는지)
- 암호화→복호화 왕복, 레코드마다 IV가 달라 같은 번호도 암호문이 다른지
- 역할별 원문 조회 허용/거부, 거부 시에도 로그가 남는지
- 원문 조회 1회당 로그 1행, 로그에 원문이 없는지
- 마스킹 규칙, 형식 검증(가짜 번호만 사용 — 실제 번호 금지)
- 키 버전이 다른 레코드 복호화

## 6. 아직 정하지 않은 것 (구현 이슈에서 질문)
- 처리 근거 개별 조문(4대보험 신고·원천징수 관련 법령) — 원문 확인 후 주석 기재
- 접속기록(조회 로그) 보관 기간과 점검 주기 — 안전성 확보조치 기준 원문 확인 필요
- 암호화 키 보관 위치(운영 환경의 비밀 저장소·KMS 선택)와 키 교체 주기
- 마스킹 시 뒷자리 첫 자리(성별 숫자)까지 보일지, 뒷자리 7자리를 모두 가릴지
  — #14 구현은 더 보수적인 "뒷자리 7자리 모두 가림"(`000000-*******`)으로 했다. 바꾸려면 `docs/employee-design.md` 4장 참고
- 퇴직자 주민등록번호 보존 기간과 파기 절차(관련 법령 보존 의무 확인 필요)
